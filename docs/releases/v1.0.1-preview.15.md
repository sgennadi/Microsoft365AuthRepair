# Microsoft 365 Auth Repair v1.0.1-preview.15

## What's new
1. **Live Microsoft 365 sign-in help:** Typing an AADSTS error, 1001, 0x80090016, or a topic such as activation now searches the built-in Microsoft Learn guide as you type. The oversized Explain code button was removed; no pasted account data is sent to a service.
2. **Full Office KMS key:** The public Microsoft GVLK appears on its own wide, selectable, read-only row, with the explanation below rather than overlapping the key.
3. **Explicit Office Preview status:** Every WMI Preview entry is summarized even if an activated Office LTSC 2024 record is selected. Preview entries without installed keys say no cleanup is necessary. A known 2024 Preview key with a separate active production license can be reviewed for a separately confirmed cleanup. With no active production license, supported key replacement still uses the existing two-consent KMS/MAK workflow. Unknown/2026 and unrelated product keys are never deleted.
4. **One Setup entry instead of Settings:** The header now opens the scope-aware wizard. Current user has a concise action selector and optional one-time portable EXE cleanup. All users retains its three-step method/timing/action wizard. Starting a repair still requires an independent confirmation (and UAC if necessary).
5. **Scheduled worker housekeeping:** The All users wizard can inspect our Task Scheduler folder read-only. Administrator-only cleanup removes only completed or expired tasks verified by name, principal SID and exact action, after an independent confirmation. Never delete running, waiting or unknown jobs. Shared protected PS1/EXE worker files are deleted only on explicit request and only when the entire Task Scheduler folder contains no jobs.
6. **Worker execution details:** PowerShell fallback is extracted into `%ProgramData%\Microsoft365AuthRepair\WamReregisterWorker.ps1`. Its task runs under the target user's interactive Windows token at logon, *not* SYSTEM. The native EXE worker uses the same protected folder. Each worker tries to delete its own one-shot task when finished; administrative housekeeping handles tasks left over.

## Verification and pilot limits
- Build, package and Windows GUI smoke tests must pass for Preview.15 before publication.
- Live cleanup requires a test VM with Windows Task Scheduler and non-production user profiles. Do not remove the shared worker if any account has pending or active tasks.
- Live Office Preview key deletion/KMS-MAK activation needs a spare licensed test machine. GitHub CI does not test destructive operations or prove Office app sign-in.
- Main UI English/Russian/Hebrew at 100–200% scaling requires workstation visual verification.
- Stable v1.0.0 remains unchanged.
