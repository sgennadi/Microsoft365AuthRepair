# Microsoft 365 Auth Repair 1.0.1-preview.7

## What's new
1. **All users → Scheduled task:** choose `EXE (recommended)` or `PowerShell script (WAM re-register only)`.
2. The **EXE** mode uses the protected local Microsoft365AuthRepair.exe worker, supporting Repair sign-in and Full identity reset.
3. The **PowerShell** mode creates a per-user task pointing to an administrator-protected standalone WamReregisterWorker.ps1 in ProgramData. This script works without either the original downloaded EXE or the protected worker EXE, as long as Windows PowerShell/AppX are allowed by policy.
4. **Only create tasks — run at next sign-in**: schedule for each existing local/domain Windows profile without immediately starting tasks in currently logged-on sessions.
5. Default remains **EXE** with immediate action for active users and deferred execution for offline profiles. Neither variant stores passwords, runs under SYSTEM or touches nonexistent profiles.
6. Explicit UAC elevation retains the selected task engine and next-sign-in-only setting; no repair starts automatically after UAC.
7. PowerShell worker validates its own run ID, expected SID, interactive session and task name, writes local result markers, and never performs the destructive Full reset.
8. Added CI checks to parse the standalone PowerShell script without executing repair; existing x64/ARM64 release and GUI checks are retained.

## Notes
- Stable v1.0.0 remains unchanged. This Preview needs controlled real-Windows Task Scheduler testing with online and offline domain users.
- `TASK_LOGON_INTERACTIVE_TOKEN` (3) requires an interactive sign-in, not a stored password. Tasks are created only for Windows profiles already present on the PC.
- Both modes currently use Windows PowerShell as a Task Scheduler COM registration bridge. In EXE mode the actual WAM registration still calls `Add-AppxPackage`. If PowerShell or AppX cmdlets are blocked by organizational policy, neither mode can guarantee repair.
- PowerShell fallback is a locally staged unsigned script. The updater does not bypass execution policies or use `-ExecutionPolicy Bypass`. Environments requiring AllSigned must allow a properly signed script, which is not yet produced by this project.
- The chosen per-user tasks are placed in Task Scheduler folder `\Microsoft365AuthRepair`, expire after 90 days, and record one attempt per user. Review local repair logs and Task Scheduler history for actual outcomes; creation is not proof of completion.
- A regular user's portable EXE may be deleted without breaking scheduled work. If both the protected EXE and the protected PowerShell script are removed, scheduled tasks cannot execute; use central GPO/Intune deployment to restore trusted workers.
- Verified CI is not a claim of physical ARM64, real WAM/Entra and domain-user task testing.
