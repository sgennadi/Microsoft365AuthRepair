# Microsoft 365 Auth Repair v1.0.2-preview.25 — live TPM / BitLocker results

**Preview only.** Stable 1.0.1 remains unchanged.

## What's new

1. **TPM & BitLocker is visible while checking.** Previously the Device Security card stayed hidden until all four top-level probes finished. It now appears directly below the progress/status banner as soon as Check & Diagnose begins, with localized **Checking…** statuses.
2. **Live, independent results.** Every completed isolated Windows device probe streams its strictly typed, read-only snapshot directly to the card. TPM readiness, Secure Boot, Memory Integrity, VM detection, DPAPI/AIK and other completed statuses appear without waiting for the BitLocker WMI probe.
3. **Honest partial evidence.** If BitLocker WMI reaches its 10-second timeout, its protection/encryption fields change from Checking to **Not verified**, while the previously collected TPM and other evidence stays visible. The final result remains **Partial**. A completed stage is not proof of healthy Office sign-in or secure hardware.
4. **Compact Cancel link.** Replaced the oversized **Cancel check** button in the status banner with a small, keyboard-accessible localized **Cancel** link in the Activity header next to **Copy log**. It only appears during a read-only scan.
5. **Safe cancellation.** Cancel stops waiting, leaves completed device-security values visible and converts unfinished fields to Not verified. It does not change TPM, BitLocker, Entra join, Office accounts, credentials, cryptographic keys or settings.
6. **Better hierarchy on narrow/high-DPI displays.** Device Security is now above Activity and the WAM result card. The TPM & BitLocker shortcut remains usable while scanning and **View full details** reuses the currently available snapshot instead of repeating a WMI query.
7. **Windows regression gates.** Added tests for partial device snapshots, pending vs unverified UI states, compact cancel control, main-screen row positions and the existing x64/ARM64/worker/privacy checks.

## On-device validation

Preview.24 field feedback showed the TPM, HVCI, Secure Boot and virtual-machine checks finished, while **BitLocker (WMI) · Time limit reached (+10s)**. This does **not** indicate BitLocker hardware or encryption failure. A raw WMI provider can time out for many reasons. Preview.25 improves visibility rather than performing invasive recovery or increasing retries.

The Activity Copy log still contains only fixed stage names, outcomes and timestamps. Local partial evidence remains inside the application and is **not** added to the anonymous diagnostics transport.

Test on the affected Windows computer at 100%, 150% and 200% DPI with English, Russian and Hebrew UI. Confirm the Device Security card is visible **during** the scan, its BitLocker fields are Not verified after a timeout, and Cancel is compact and accessible. Microsoft 365 real application sign-in must still be tested independently.
