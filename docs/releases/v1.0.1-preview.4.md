# Microsoft 365 Auth Repair 1.0.1-preview.4

## What's new
1. The scope selector shows **Current user — DOMAIN\\username**, using the actual desktop owner even when UAC runs as a different admin.
2. **All users on this PC** replaces the confusing `All local Windows profiles` wording. This covers existing local and domain user profiles on the PC.
3. Current-user Repair and Full identity reset do not require UAC; Full reset remains destructive and requires explicit confirmation.
4. Choosing **All users** without admin rights asks for permission, opens a new elevated instance with All users selected, but does **not** start any operation without another confirmation. Online/offline users are handled by per-user scheduled tasks.
5. Advanced now displays target scope and permissions clearly, with localized EN/RU/HE explanations.
6. Diagnostics & Reports includes **Check receiver** for live shared Google gateway schema v3 and a specific explanation of `not_configured` with the `GITHUB_M365_ISSUES_TOKEN` script property.
7. Failed or unconfirmed report submissions remain in the local pending queue. No credentials, tokens or raw logs are sent.

## Notes and limitations
- Existing **Stable v1.0.0** is unchanged. Use this Preview for controlled testing only.
- `not_configured` means the deployed shared Google Apps Script cannot find the M365 PAT property. Add `GITHUB_M365_ISSUES_TOKEN` in the **same script project behind the application's /exec URL**. Script-property changes take effect without redeployment if v3 is already live; a code update requires Deploy > Manage deployments > New version.
- Public GitHub Issues are not private. Sending requires a reviewed report and an explicit consent checkbox; a live Issue receipt must be returned to confirm delivery.
- WAM/Entra repair, all-users scheduling, actual UAC, real update replacement and ARM64 on physical hardware still require operator pilot validation. Compilation and GUI smoke tests alone are insufficient.
