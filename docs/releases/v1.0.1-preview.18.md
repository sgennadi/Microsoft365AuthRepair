# Microsoft 365 Auth Repair v1.0.1-preview.18

## What's new

1. **Smart Repair Engine** — evidence-based recommendation based on WAM/BrokerPlugin, Entra device authentication, PRT, Office installed edition and read-only preflight. Device trust errors do **not** prompt destructive Office cache deletion; missing data is not treated as success.
2. **Preflight before repair** — detects open Office/Teams applications, advisory AppX deployment restrictions, HTTPS reachability of Microsoft login and Windows clock drift based on HTTPS Date. Refuses immediate full reset when Office applications are open; no network probe is treated as successful login.
3. **Office activation health** — separates supported 2024 Volume KMS/MAK/Visio/Project WMI inventory from Microsoft 365 subscription. For subscriptions, optionally runs Microsoft's installed local `vnextdiag.ps1 -action list` under current user and extracts only recognized state words (no raw license output, UPN, tenant data). PowerShell policies are respected.
4. **All users task retry** — in the status viewer only a *confirmed failed WAM registration* can be explicitly re-queued for the selected existing Windows profile at its **next sign-in**, after a second confirmation. Office identity reset, unconfirmed states and concurrent per-user tasks are never auto-retried.
5. **Optional Entra sign-in audit** — read-only Microsoft Graph lookup by Correlation ID, using Device Code (delegated) or a configured certificate (application). Auth implementation follows BitKeyBridge's session/cache/certificate assertion patterns but is isolated from its BitLocker/LAPS/Intune privileges. **Only AuditLog.Read.All** may be used; extra Graph application roles are rejected, and certificate mode needs its *own audit-only* App Registration and admin consent. No ROPC, saved token, passwords or Graph write operations. A valid admin role and supported Entra licensing may be needed.
6. **Verify repair** — after a successful direct Current user repair, local diagnostics refresh automatically. An explicit user report confirms whether they successfully signed in to Word, Outlook or Teams. No application sign-in is falsely marked as verified by local WAM or Graph metadata.
7. **UI polish and localization** — compact, responsive Smart Repair summary with clear next action, read-only evidence, optional Graph link and separate sign-in verification; EN/RU/HE strings with DPI-aware wrapping. Graph review has no background login.

## Guardrails and pilot limitations

- Stable v1.0.0 unchanged. Current-user WAM registration/full reset and all-user scheduling still require the same explicit prompts and privileges. Smart Repair never executes a destructive change automatically.
- HTTPS HEAD reachability, clock check, vNext state parsers and Graph metadata are advisory local or authorized read-only signals, **not proof of authenticating in Office**.
- Graph Device Code requires an organization-approved public-client application (AuditLog.Read.All delegated) and an authorized reader. Certificate needs exact tenant/client/certificate and a dedicated app granted only AuditLog.Read.All application role. Neither mode creates applications or grants permissions.
- Graph token cache is **process-only**; reopening the dialog in the same process can reuse a valid matching token. Close the app or choose Disconnect to discard the cached reference.
- Only an explicit operator action can retry a failed WAM task; scheduling runs using the affected user's interactive logon token.
- Microsoft Graph network access, real Entra sign-in log permissions, Windows service environments, actual Office/Visio activation, queued tasks, and 100/150/200% DPI/HE RTL require pilot testing on a disposable Windows machine. GitHub Actions exercises compilation, self-tests, and guard logic, not a live tenant.
