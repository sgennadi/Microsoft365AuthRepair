# Microsoft 365 Auth Repair 1.0.1-preview.9

## What's new
1. **Settings** replaces the largely empty Advanced checkbox. Per-user WAM/Office repair and reset remain separate on the main screen; settings now group all-user scheduled-task execution and optional portable EXE cleanup.
2. **All users** settings offer EXE (recommended) or PowerShell (WAM re-registration only) and optional next-sign-in-only scheduling. The main window summarizes the current choices. Existing UAC, confirmation, per-user token and protected-worker rules are unchanged.
3. **Cleanup** can remove only the eligible standard user's own portable EXE after a successful current-user operation. It is disabled otherwise, never deletes the protected worker, and defaults off.
4. **Check & Diagnose** interprets read-only Entra/WAM signals into Healthy prerequisites, Attention required, or Repair recommended. It explains BrokerPlugin, PRT and Entra device trust problems, with next steps; successful prerequisites are explicitly NOT proof that Office, Teams or OneDrive sign-in succeeds.
5. **Report submission**: Generate report (or Load pending JSON) opens a separate review-and-send dialog immediately. The requested *I approve sending...* checkbox is checked initially, but no data uploads without a deliberate **Send anonymously** click. The dialog previews the exact allowlisted JSON and public GitHub Issue destination; **Keep local** leaves the report queued.
6. **Simpler diagnostics UI** removes redundant Check receiver buttons. Confirmed GitHub submissions still close automatically; rejected ones keep the report local and show the gateway error code and relevant advice. No silent upload or retry is introduced.
7. User-facing new settings, report confirmation and diagnostic findings have English, Russian and Hebrew labels. Modern buttons/icons, DPI-aware sizing and accessibility behavior are preserved.
8. Repair, full-reset, scheduled-worker, updater and Google Apps Script receiver algorithms remain unchanged. Stable v1.0.0 is untouched.

## QA
- Pull-request CI builds x64 and ARM64 self-contained EXEs and runs the Windows x64 GUI smoke tests.
- The GUI self-test checks Settings, report consent default, icon rendering, button layout and deterministic WAM diagnostic interpretation. It neither sends a report nor repairs Microsoft accounts.
- Real Windows 100%, 150%, and 200% DPI, RTL, elevated sessions, x64 and ARM64 field behavior require user acceptance testing.
- If an error occurs after Send, check GitHub Issues before retrying because a timeout is not proof that no Issue was created.
- The Google receiver must remain deployed with schema v3; this release does not modify the server or GitHub tokens.
