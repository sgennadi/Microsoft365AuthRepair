# Microsoft 365 Auth Repair v1.0.1 (Stable)

**Release date:** November 16, 2026. This is the first stable release of the consolidated Smart Repair Center, succeeding v1.0.0. Windows x64 and ARM64 are packaged as separate self-contained, single-EXE ZIP archives.

## What's new

1. **Smart Repair Center:** local, evidence-based WAM/Entra/Office guidance. Missing BrokerPlugin and missing PRT are distinguished from device-trust or MFA/Conditional Access errors. Repairs are not started automatically.
2. **Safe preflight:** read-only checks for running Office/Teams applications, Microsoft login HTTPS transport, time skew and AppX policy hints. Full identity reset pauses when executing it immediately would conflict with open Office apps.
3. **Office 2024 and Microsoft 365 licensing:** separate Office, Visio and Project Volume KMS/MAK support, read-only 365 subscription information, exact 2024 GVLK matching, and explicitly confirmed cleanup of verifiable outdated Preview keys only. Unsupported/unknown 2026 Preview keys remain read-only.
4. **Clear licensing records:** installed Office editions are presented first. Extra WMI licensing/template records are explicitly labeled as **not additional installations**. Keyless records are labeled as templates, and an already activated production license is not replaced.
5. **Anonymous Office diagnostics:** the explicitly reviewed and approved diagnostic report now includes Office installed family/edition, aggregated activation status and *coarse* licensing/Preview record counts. It never includes a MAK or full/partial key, KMS hostname, product GUID, tenant/account name, installation path, raw WMI/Graph data or Office token. Previously saved WAM-only reports remain compatible and receive an unknown Office state. A report is never uploaded without a separate Send click; its GitHub Issue is public.
6. **All users controlled repairs:** a single three-step administrator wizard schedules EXE/PowerShell WAM workers only for existing profiles and shows protected per-user task status. Explicit next-sign-in retry is available only for a selected, confirmed failed WAM re-registration; a full reset is never auto-retried.
7. **Optional Graph sign-in audit:** reusable in-process Device Code or certificate session modeled after BitKeyBridge, limited to `AuditLog.Read.All`; a dedicated audit-only Entra app is required. No ROPC, password collection, cloud write access, BitLocker/LAPS/Intune grants or persistent token cache.
8. **Honest post-repair verification:** successful local WAM recheck does not imply Office sign-in. The affected user explicitly reports whether Word/Outlook/Teams sign-in worked.
9. **Usability and updates:** compact Windows-style native controls, English/Russian/Hebrew interface, per-monitor DPI and High Contrast handling, numbered What's New, Stable/Preview SemVer update checks with package SHA-256 and architecture verification and rollback-aware updater.

## Security, quality and compatibility

- Requires Windows with the appropriate x64 or ARM64 architecture. No installed .NET runtime is required; each ZIP includes one self-contained `Microsoft365AuthRepair.exe`.
- Simply launching or generating a local report makes **no** account, key, domain join or cloud changes. Destructive operations require the existing distinct confirmation(s). Do not test full Office identity reset on a live working profile.
- `AuditLog.Read.All` in Graph requires organization-approved app permissions, admin consent, an authorized reader and potentially Entra licensing; the Graph feature is optional and read-only.
- **Verification scope:** GitHub Windows CI compiles both architectures, runs x64 WinForms and pure regression/security self-tests, validates the scripts, and verifies release ZIP SHA-256 and contents. Live Microsoft 365 sign-in, Office KMS/MAK activation, domain multi-user scheduling, physical ARM64 hardware and visual RTL at 100/150/200% DPI have **not** been independently certified. Pilot-test on expendable Windows profiles before organization-wide deployment.
- A passing CI build or a **Stable** version label is not an enterprise certification; additional field QA is required.
