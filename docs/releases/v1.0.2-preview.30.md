# Microsoft 365 Auth Repair v1.0.2-preview.30 — clearer security and reporting

**Preview only. Stable 1.0.1 is unchanged.**

## Interface

1. The banner no longer contains an extra **TPM & BitLocker** jump that leads to a card already on the main page. TPM/BitLocker evidence remains visible even when WAM/Office diagnostic results are collapsed.
2. **Show WAM / Office results** and **Hide WAM / Office results** have explicit scope, avoiding accidental hiding of Windows device-security evidence.
3. **Show activity log** now expands the existing local Activity journal, and **Hide activity log** collapses it. The journal expands during Check & Diagnose for live stage and timeout results and is collapsed afterward. Copy log still works when the journal is shown.
4. **View full details** opens a more compact Windows inspector with clearly titled TPM, OS BitLocker, platform security and DPAPI/attestation sections. Values use readable labels rather than one massive raw text block. Refresh still executes independent read-only provider probes; Advanced operations remain separately confirmed.

## Diagnostics & Reports

5. Report generation now runs native device checks in bounded isolated child processes (no direct blocking WMI capture), preserving available fields when one provider times out and recording whether coverage is COMPLETE, PARTIAL or NOT_VERIFIED.
6. The public diagnostic event has 29 **categorical**, strictly allowlisted signals: six Entra/WAM statuses, seven coarse Office licensing statuses, and 16 device/attestation/security categories. Added values are **Secure Boot state**, **Memory Integrity configured state** and **device probe coverage**.
7. User-visible **Send anonymously** preview and explicit consent remain mandatory. No raw dsregcmd output, BitLocker recovery secrets, TPM lockout/firmware version, third-party product labels, user/device IDs, domains or credential details are sent.
8. Before POST the client requires the shared gateway to advertise **gateway_schema_version 4** with **microsoft365-auth-repair/v2** capability. Old v3 gateways will show an actionable deployment message rather than `invalid_evidence`; no fallback drops diagnostic evidence silently. Older saved local report files remain readable and missing coverage defaults to NOT_VERIFIED.

## Receiver deployment (external prerequisite)

The corresponding Code.gs and offline tests are tracked in [TermsrvPatcherUnified PR #55](https://github.com/sgennadi/TermsrvPatcherUnified/pull/55). **Merging GitHub code does not deploy Google Apps Script.** The Apps Script owner must replace Code.gs, Save, select **Deploy > Manage deployments > Edit > New version > Deploy**, and verify the existing /exec GET reports gateway schema 4 and M365 v2 support.

Keep the deployed HTTPS URL, server-only token and Termsrv reporting contract unchanged.

## Field verification

Test the GUI at 100/150/200% DPI in EN/RU/HE. Confirm no top-bar link duplicates the TPM card, the WAM collapse does not hide TPM, Activity toggles logically, the security details do not clip, and reports remain local unless submitted after reviewing the allowlisted JSON.
