# Microsoft 365 Auth Repair v1.0.2-preview.19 — TPM / BitLocker diagnostics

**Test release**, succeeding Stable v1.0.1. Version is 1.0.2-preview.19 (not 1.0.1-preview.19) so opting into Preview can update an existing Stable 1.0.1 installation without violating SemVer ordering. Stable 1.0.1 is unchanged.

## What's new

1. **TPM readiness (read-only):** query Windows `Win32_Tpm` for presence, specification, IsReady, Enabled, Activated and Owned flags. Unknown/permissions failure is *not* reported as TPM absence or failure.
2. **BitLocker OS-volume state:** report the current protection and encryption/conversion state of the **system drive only** via `Win32_EncryptableVolume`. The tool does not enumerate key protectors or request, back up, reveal, export or rotate recovery passwords.
3. **DPAPI & domain connectivity:** show the *presence/category* of `ProtectionPolicy`, read-only domain membership, and optional bounded `nltest /dsgetdc:<domain> /writable /force` discovery. If a writable DC is unavailable, highlight potential DPAPI first-logon/key-backup issues without asserting TPM hardware failure or changing policy. No DC hostname, IP or domain is included in the report.
4. **TPM attestation and Windows 11:** read existing `AIKEnrollmentErrorCode` **if present** and `Win32_Tpm.IsReadyInformation` for EK-certificate provisioning warnings. Display an allowlisted TPM vendor class, local-only firmware version and approximate Windows release. `0x80070490` means NOT_FOUND; `0x800705B4` means TIMEOUT. No attestation enrollment or EK-key read/export is performed. Absence of an error record does not establish attestation success.
5. **Office error guidance:** recognize `0x80090016` (also decimal -2146893802), `0x80090030`, `0x80090031`, `0x80090034`, `0x80090035`, `0xC0090016`, `0x80070490`, `0x800705B4`. Separate cryptographic keyset, DPAPI/RWDC, TPM readiness and device attestation recommendations. An Office error code is never automatic proof of a defective TPM.
6. **Smart Repair integration:** add concise TPM/BitLocker, AIK attestation and writable DC warnings within **Check & Diagnose**, plus a separate localized read-only TPM & BitLocker inspection dialog. Review prerequisites before any WAM or Office reset.
7. **Privacy-safe reports and interface:** reviewed anonymous diagnostic reports add only allowlisted TPM/BitLocker, attestation and DPAPI status *categories*. They never send a key, key suffix, EK certificate, firmware build, TPM ID, tenant, domain/DC name, profile ID, location or raw event-log contents. A responsive, scrollable EN/RU/HE dialog wraps long explanations at high DPI.

## Safety and test boundaries

- No Clear TPM, BitLocker suspension/disabling, key or protector enumeration, NGC/BrokerPlugin removal, `dsregcmd /leave`, `certreq -enrollaik`, driver/firmware installation, `ProtectionPolicy` mutation, credential removal or enterprise-policy changes are introduced by this module.
- IsReadyInformation and some WMI security APIs may require local administrator rights. Without them, indicators remain UNKNOWN; the program never self-elevates merely for this read-only inspection.
- AIK enrollment codes are taken only from existing local state when present and must be interpreted with Windows/Entra logs. EK provisioning-warning bits do not establish physical TPM health or validity of a manufacturer's EK certificate chain.
- GitHub CI validates WinForms/Windows x64 and ARM64 builds and static/pure safety checks. Actual BitLocker-protected disks, domain RWDC reachability, Entra/Autopilot attestation, physical ARM64 hardware and 100/150/200% DPI RTL rendering need a controlled device pilot before Stable promotion.
- `v1.0.1` Stable stays the latest Stable and does not automatically update to this Preview unless the user opts into previews.
