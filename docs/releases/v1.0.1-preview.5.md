# Microsoft 365 Auth Repair v1.0.1-preview.5

## What's new

1. **Update** now completes automatic EXE replacement, verification, rollback and restart. A normal writable installation needs no UAC or manual copying.
2. In Program Files or the protected machine folder, Update asks for explicit UAC permission if needed. The elevated updater uses administrator-protected storage, validates a fresh package again and installs safely.
3. **All users** supports existing profiles now or at their next sign-in, and optionally includes users who have **never** used this PC: one-time repair at first sign-in for 90 days.
4. A first-sign-in campaign runs under each real user's interactive identity, stores no user passwords and excludes pre-existing profiles to prevent double resets.
5. An optional Advanced checkbox removes the user's own portable EXE after a successful current-user repair. The shared protected all-users worker is retained for offline users.
6. Progress, short numbered What's New, DPI-aware buttons, x64/ARM64 builds and consented anonymous diagnostics remain available.

## Usage and limitations

- If your currently installed build already has **Update** (Preview.3 or Preview.4), select **Preview + Stable** and click **Update**. This build cannot retrofit that action into older installers that only offer **Download & verify**.
- Only the account running the program can modify its WAM state. **Without an interactive sign-in**, Windows cannot run AAD BrokerPlugin registration for another user's identity. A new user with no local profile is prepared, not repaired yet; their one-time task runs when they actually sign in.
- Admin consent is required to install the all-users campaign. Under Admin approval, only the shared protected worker and HKLM startup registration persist (90-day expiry check); successful per-user runs do not delete the shared copy while other accounts are still pending.
- The portable-cleanup checkbox is **opt-in** and restricted to the current standard user's own profile. The .NET helper may leave temporary cleanup files subject to OS cleanup.
- The protected-folder automatic update path and rollback, the HKLM Run first-sign-in path, per-user scheduled tasks and real WAM repair are not yet validated on your production machines. Pilot before any broad deployment.
- Stable v1.0.0 is not changed.
