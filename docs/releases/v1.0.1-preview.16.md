# Microsoft 365 Auth Repair v1.0.1-preview.16

## What's new

1. **Direct Current user workflow.** Removed redundant Current user setup wizard and PortableSelfCleanup helper entirely. There is no option or background mechanism to delete the running portable EXE. Current-user WAM re-registration and last-resort Office identity reset remain separately confirmed main-screen actions.
2. **All users has one workflow.** Selecting All users opens the existing three-step wizard (worker mode, when to run, what to do). A compact All users setup link reopens it. Duplicate main-screen WAM/reset buttons are hidden when All users is selected; they return with Current user.
3. **See scope before changing anything.** The confirmation now shows an exact count of existing Windows profiles at review time, an estimate of which will start immediately, and the remainder scheduled for their next sign-in. Only the reviewed profiles are scheduled. New accounts without profiles are not enrolled.
4. **Read-only recheck after repair.** After successful *direct, unelevated* current-user WAM re-registration or Office sign-in reset, the existing health diagnosis runs automatically. This checks WAM/Entra/Office prerequisites, not actual successful Word, Outlook, Teams or OneDrive authentication. Tasks scheduled for another session are never reported as finished by this recheck.
5. **Less clutter.** Removed the separate Open local logs button on the main screen. Compact links to both repair logs and the local report queue now live under Diagnostics & reports.
6. **More accurate wizard wording.** The passive action is now “No action — keep choices for this session” instead of “Save settings only”; the summary identifies the selected repair action. No unsupported claim of persistent task preferences.
7. **Safety unchanged.** All-user UAC, consent before any action, no auto-deletion of pending user tasks, user-scoped identity protection, preview/Stable channel order and privacy-safe diagnostic sending remain in place. Stable v1.0.0 is unchanged.

## Verification and pilot limits

- Windows x64/ARM64 build and WinForms smoke tests must pass before release.
- Automated checks cover direct-user vs all-user scope, visible UI and the post-repair recheck gating.
- CI cannot prove interactive task launch for domain profiles, successful live Office sign-in, recovery from an identity reset, or DPI/RTL visual correctness. Pilot on a non-production Windows PC, including 100/150/200% scaling, before Stable promotion.
- A registered all-user task is **queued**, not necessarily successfully completed. Running and pending tasks remain protected from maintenance cleanup.
