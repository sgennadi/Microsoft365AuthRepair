# Microsoft 365 Auth Repair v1.0.2-preview.20 — Entra device keys and TPM lockout

**Test release**, extending Preview.19 and newer than Stable 1.0.1. Stable production remains unchanged.

## What's new

1. **Entra device key evidence:** include only `TpmProtected`, `KeySignTest` and `AadRecoveryEnabled` from `dsregcmd /status`, never raw key/container IDs, thumbprints, device IDs, tenant IDs or certificates. `KeySignTest` requires elevation; inaccessible/absent results are UNKNOWN, not failure.
2. **Windows Hello for the signed-in account:** `NgcSet` indicates Windows Hello enrollment, not whether Office sign-in succeeded. `NO` is neutral, and inspecting a different elevated administrator is explicitly flagged.
3. **TPM lockout:** read only the `Get-Tpm.LockedOut` boolean, if available, through a bounded Windows PowerShell probe. Show local lockout status in the existing TPM & BitLocker inspector, prioritized as review-only. No owner-authorization, lockout reset, TPM clear or repeated key attempts.
4. **Smart Repair:** put verified Entra device-key signing/recovery failures ahead of BrokerPlugin re-registration, without offering an inappropriate WAM repair. Keep Preview.19 DPAPI, writable DC, AIK, BitLocker, Office and hardware checks.
5. **Error search:** explain cryptographic errors `0x80090011`, `0x80090016`, `0x80090030`, `0x80090031`, `0x80090034` using localized guidance and Microsoft Learn reference material.
6. **High DPI / privacy:** two extra compact, DPI-responsive sign-in tiles and negative regression tests confirm `KeySignTest`, TPM lockout, `NgcKeyId` and key-container information never enter anonymous reports. The existing Preview.19 coarse TPM/BitLocker/DPAPI report categories remain unchanged.

## Field testing required

- Windows x64/ARM64 CI compiles and checks WinForms/self-tests, but cannot prove hardware TPM/BitLocker, real Windows Hello enrollment, Entra sign-in, AIK enrollment or RDS/AD operation.
- Test with the *affected* Windows desktop account and, if needed, have IT perform a separate authorized elevated device-key check. Never interpret a missing `KeySignTest` result as FAILED.
- The tool never disables WAM/ADAL, clears TPM, resets PIN/NGC, changes DPAPI policy, deletes key containers, removes BitLocker protectors or disconnects Entra.
- Before **any separate** hardware/device-recovery procedure, IT should ensure BitLocker recovery material is available.
- Visual QA at 100/150/200% DPI, Windows High Contrast and Hebrew RTL remains necessary before Stable promotion.
