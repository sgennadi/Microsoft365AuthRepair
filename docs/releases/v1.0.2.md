# Microsoft 365 Auth Repair v1.0.2 — Stable

Release date: 2026-11-16. Windows x64 and ARM64, single portable EXE per ZIP.

## Usability and display fixes

- The WAM/Office diagnostic summary appears immediately under the result banner. TPM/BitLocker remains a separate read-only card below it.
- The main window uses a scrollable viewport with content-sized rows; the lower part can be scrolled into view instead of being clipped by a fixed-height table layout, including on high-DPI monitors.
- **Show/Hide WAM / Office results** and **Show/Hide activity log** actually change table row heights and update their labels; the device-security card remains available.
- **Review & send diagnostic report** shows the JSON from its first character, without blue Select All highlighting. It stays read-only but can be manually selected/copied. Initial focus is on **Keep local**, not Send.
- Compact, grouped Advanced device-security controls and read-only status inspector remain available.

## Diagnostics and safe operations

- Independent, timeout-bounded local probes show TPM, OS-volume BitLocker status, Secure Boot, HVCI, domain/DC and DPAPI categories. UNKNOWN means not verified, not healthy or broken.
- Report capture does not block indefinitely on one hardware WMI provider. Its outbound report contains 29 typed category-only fields; it does not include recovery keys, Office license keys, TPM firmware versions, user/tenant IDs, paths or raw logs.
- Admin-only BitLocker operations require checked risk acknowledgment, exact typed command and a separate approval. No automatic TPM Clear, device rejoin or destructive changes during diagnosis.
- Current-user and All-users WAM workflows, non-destructive guidance, Office/Visio/Project licensing tools and updater security checks are retained.

## Shared receiver requirement

The existing [Code.gs](https://github.com/sgennadi/TermsrvPatcherUnified/blob/main/integrations/google-apps-script/Code.gs) supports the M365 expanded report contract **only after its owner deploys Gateway v4** (GET `gateway_schema_version: 4`, capability `microsoft365-auth-repair/v2`). Update the **same** Apps Script deployment: Save → Deploy → Manage deployments → Edit → New version → Deploy. Do not rotate/change the existing URL or tokens. Until then, the application will preserve reports locally and explain why Send cannot proceed. Public uploads remain opt-in.

## Testing and known limits

Windows x64/ARM64 CI compiles, runs UI self-tests and validates package contents and SHA-256. Physical visual checks at 100/150/200% scaling, all UI languages (EN/RU/HE), real domain GPO effects and Microsoft 365 cloud sign-in are separate field acceptance checks. No automated test proves that a Microsoft 365 sign-in succeeds.
