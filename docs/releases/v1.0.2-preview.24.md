# Microsoft 365 Auth Repair v1.0.2-preview.24

**Preview only — Stable 1.0.1 unchanged.** Builds on the dedicated Device Security card in Preview.23.

## What's new

1. **Secure Boot and firmware:** read-only UEFI/legacy BIOS detection using Windows GetFirmwareType and the system Secure Boot state. Shows **On**, **Off**, **Legacy BIOS** or **Not verified**. Never changes firmware settings.
2. **TPM version:** displays Windows-reported TPM specification **2.0**, **1.2** or **Not verified**.
3. **Security processor:** shows TPM detected/available, not ready, missing or unverified using existing Windows TPM WMI evidence. This does not establish Windows Hello or Microsoft 365 app sign-in success.
4. **Memory Integrity / HVCI:** combines runtime and policy state, distinguishing enabled-and-running, enabled-but-not-running, disabled, not configured and unknown. Enabled-but-not-running warrants review.
5. **Virtual machine detection:** shows whether Windows is an identified guest and a fixed allowlisted platform label: VMware, Hyper-V, KVM/QEMU (including Proxmox guests), VirtualBox, Xen, Parallels, Nutanix, Amazon EC2, Google Cloud or other VM. Physical OEM identification is reported as **No VM indicators (OEM)**, not proof the system cannot be virtualized. Merely running Hyper-V or VBS on a physical PC does not make it a VM guest.
6. **Independent timed checks:** Secure Boot and VM detection run in separate, read-only subprocesses under the existing per-probe **10-second timeout**, with up to three checks concurrently. A hanging WMI query cannot indefinitely block Check & Diagnose.
7. **Status and details:** two more sanitized Activity stages, four more Device Security tiles (12 total), and additional read-only fields in **View full details**. Stage-copy logs contain no machine model, serial number, TPM key, UPN or recovery material.
8. **Regression checks:** test guest-vs-host detection, allowlisted local IPC serialization, privacy-safe values and the Device Security card.

## Security and validation

This preview reads local firmware state, TPM/BitLocker/Device Guard information and standard Windows computer-system manufacturer/model only to classify the guest platform **in memory**. The raw manufacturer/model and other identifying data are not written into the activity log, anonymous diagnostic uploads or the snapshot. It does **not** write registry or UEFI settings, clear TPM, modify BitLocker, export keys, change Windows Hello or sign-in state.

A virtual TPM/vTPM or Secure Boot in a VM may be reported; these checks do not prove physical hardware. Windows CI tests x64 and ARM64 and a Windows GUI smoke test; actual enterprise firmware, virtual machines, high-DPI (200%) and EN/RU/HE RTL must be verified on physical/guest Windows systems before any Stable promotion.
