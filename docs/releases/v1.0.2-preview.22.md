# Microsoft 365 Auth Repair 1.0.2-preview.22 — isolated device health checks

**Preview only.** The published Stable 1.0.1 is unchanged. Preview.21 demonstrated that WAM/Entra, Office licensing, and network preflight complete in under one second while the combined TPM/BitLocker task remains incomplete at the 60-second UI deadline. **This is an incomplete probe, not proof of faulty TPM or BitLocker hardware.**

## What's new

1. Replaced the single serial TPM/BitLocker WMI scan with six **independent read-only checks**: `TPM_WMI`, `BITLOCKER_WMI`, `DEVICE_GUARD_WMI`, `DOMAIN_RWDC`, `TPM_LOCKOUT` and `DPAPI_ATTESTATION`.
2. Each check runs in a separate child process of the application, with a **10-second limit**. Up to three run concurrently. A stuck native WMI or Get-Tpm call no longer prevents other device results from being collected, and the hung read-only client is terminated on timeout. This does **not** restart Windows WMI, clear TPM, modify BitLocker or reset credentials.
3. The Activity panel reports each individual step as Started, Finished, Not verified, or Time limit reached. Its Copy log action records **only** fixed step labels, outcomes, timestamps and elapsed seconds, not raw WMI output, usernames, IDs or paths.
4. Partial snapshots retain any successful TPM, BitLocker, Device Guard, domain controller, DPAPI, AIK and OS-release evidence while marking blocked or unavailable provider checks **not verified**. WAM one-click repair remains hidden when the device-security evidence is incomplete.
5. The separate TPM & BitLocker inspector also uses the isolated scanner. When information is partial it says so rather than freezing on a native provider.
6. Added regression tests for the worker argument allowlist, read-only data serialization/parsing, and privacy-safe substage logging. Windows CI builds x64 and ARM64 and tests the GUI.

## Pilot and safety notes

- Real on-device Windows WMI hangs and TPM hardware cannot be reproduced by CI. Verify the six-stage Activity log on the machine that showed the 60-second timeout.
- A `Finished` stage only means that its Windows provider returned a recognized result. It **does not** prove Office authentication, BitLocker recovery or TPM hardware integrity.
- Commands only read local WMI/registry and categorised TPM status; no `Clear-Tpm`, PIN reset, `Remove-Item`, BitLocker key/protector export, Entra leave, certificate export or credentials access.
- New subprocess output is a small, machine-local JSON envelope containing only the typed, non-identifying snapshot. It is not sent to the UniversalDiagnostics receiver; the existing sanitized anonymous report schema is unchanged.
- Test 100%/150%/200% display scaling and EN/RU/HE localization on physical Windows equipment before any Stable promotion.
