# Microsoft 365 Auth Repair v1.0.2-preview.26 — independent BitLocker diagnostics

**Preview only.** Stable 1.0.1 is not modified.

## What's new

1. **Independent BitLocker results.** Check & Diagnose now reads system-drive BitLocker protection and encryption/conversion state in *separate* isolated read-only processes. Previously both lived in one WMI call chain, so a blocked GetConversionStatus could discard an already-read ProtectionStatus. A returned protection result now survives an unrelated conversion timeout.
2. **Restrict WMI to the system volume.** Queries use only the validated ASCII drive letter from Windows SystemDrive (e.g. C:) in the fixed Win32_EncryptableVolume namespace. No enumeration of data, removable or recovery volumes is needed, and no recovery secrets or protector IDs are requested.
3. **Independent deadlines.** Each BitLocker part has an existing 10-second process deadline, with at most three read-only child probes running concurrently. Conversion may be Not verified while protection is known, or vice versa. A failed/blocked WMI provider is *not* proof that BitLocker is disabled or encryption is broken.
4. **Explicit Activity labels.** BitLocker protection (WMI) and BitLocker encryption (WMI) appear separately in the local Activity journal, with EN/RU/HE labels and independent Finished, Not verified, or Time limit reached outcomes. Copy log remains stage-only and contains no user or device identifiers.
5. **Regression protection.** Added typed IPC allowlist cases and self-tests ensuring that protection and conversion remain independent and that malformed system-volume WQL input is rejected. All other security, WAM and Office scans continue unchanged.

## Safety

- No TPM clear, BitLocker disable/suspend/decrypt, protector changes, recovery-key reads, WAM reset or deletion occurs in Check & Diagnose.
- Only the validated status categories are held locally for the Device Security card. Public anonymous reporting continues to use the existing allowlisted hardware-state summary; no raw WMI values are exposed.
- A provider timeout still yields **Not verified**. This is intentionally distinct from **Off**, **Not encrypted**, or a verified Windows security failure.

## Windows verification

On the affected Windows 11 workstation, upgrade to Preview.26 and run **Check & Diagnose** with the same user context. Review **BitLocker protection (WMI)** and **BitLocker encryption (WMI)** separately in Activity. If one times out, verify the other returns independently. Use **View full details** to inspect the local read-only summary.

For independent operator verification (outside this app), Microsoft-supported `manage-bde -status %SystemDrive%` can be run in an elevated command prompt. It is read-only and may itself depend on Windows BitLocker services; do not send its output to public issues without reviewing it for identifying data.

Preview.26 requires real-world testing at 100%, 150%, 200% DPI in EN/RU/HE and on the affected machine before considering a Stable release.
