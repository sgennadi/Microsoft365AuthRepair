# Microsoft 365 Auth Repair 1.0.1-preview.8

## What's new
1. Clear, separate actions: **Check Entra / WAM**, **Re-register WAM**, and **Reset Office sign-in** instead of the ambiguous **Repair sign-in**.
2. Read-only diagnostics, nondestructive re-registration, and identity-cache deletion are now explained directly in the main window.
3. Re-register WAM requests explicit confirmation even for the current user; it does not delete cached credentials.
4. The destructive Office/WAM reset is a separate visible action with sign-out warning and existing confirmation.
5. Buttons use a subtle Windows-inspired 3D gradient and beveled border, paint all corners, and remain DPI/RTL/keyboard/high-contrast aware.
6. No changes to existing WAM repair, full-reset, all-users scheduling, or shared diagnostic report upload algorithms.
7. GitHub diagnostic Issue #1 received successfully; all six reported signals indicate healthy Entra/WAM device status, not proof that Office sign-in succeeds.

## Notes
- This is a Preview. Test actual Windows DPI 100%, 150%, 200%, all-user tasks, and UI accessibility before stable.
- **Re-register WAM** invokes Add-AppxPackage registration of Microsoft.AAD.BrokerPlugin for the selected interactive user; dependent Microsoft applications may close, but it preserves sign-in caches.
- **Reset Office sign-in** removes targeted Office and WAM credential/cache entries then re-registers the broker. Affected users will need to authenticate again.
- The shared Google Apps Script and Termsrv tokens are unchanged. Do not include GitHub PATs in the EXE.
- Stable v1.0.0 remains unchanged.
