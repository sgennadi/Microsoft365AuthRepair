# Microsoft 365 Auth Repair v1.0.1-preview.3

## What's new
1. **Update** button now downloads, verifies, safely replaces the EXE and restarts with a post-update self-test, using the shared UniversalUpdater transaction and .bak rollback.
2. Unified modern rounded, DPI-aware and keyboard-friendly buttons in Main, Update Center and Diagnostics & Reports.
3. Larger dialogs and clearer hierarchy: Update is the main action. Switching Stable/Preview checks immediately.
4. Real progress shows percentage and MiB. You can cancel transfers, open the verified download folder and read short numbered What's New.
5. Current version and its changes are visible even when no update is available.
6. Diagnostic report delivery still requires explicit review and consent. No report is treated as delivered without a GitHub Issue receipt.

## Update safety and field-testing notes

- Auto-update does **not** request UAC, does not install under elevated identity and does not update from network shares. Elevated, read-only and protected installations use a verified-package manual fallback instead of dangerous temporary executables.
- The helper runs as the same standard Windows user, only after the original process exits. It uses the canonical UniversalUpdater.Core transaction, a .bak rollback checkpoint, SHA-256 and PE-architecture checks, and a real `--ui-self-test` of the installed EXE before marking success.
- The first upgrade from an earlier preview with only "Download & verify" must still be installed manually. From this preview onward, the **next** update can be installed with one click.
- Windows x64 CI compiles and runs GUI-only self-tests. Actual app self-replacement, domain/WAM remediation, elevated paths and physical ARM64 execution require pilot verification. No false production-certification claim.
- Stable `v1.0.0` remains untouched.
- The shared Google diagnostic receiver still requires the owner's Apps Script deployment update and dedicated `GITHUB_M365_ISSUES_TOKEN`; no GitHub token is shipped in the application.
